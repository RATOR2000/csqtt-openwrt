# Сборка и предварительный выпуск

## GitHub Actions

Workflow `Validate and build` проверяет Node/Go, Rust, Android и политику
через настоящий ucode, dnsmasq и nftables в изолированных Linux namespaces.
После успешных проверок собирает пакеты SDK OpenWrt 25.12.5 для GL-MT6000.
Нативная проверка APK использует временные ключи и отдельные каталоги:
проверяет подписи собранных пакетов, конфликты DNS, кеш зависимостей,
установку без сети и восстановление исходного тестового пакета.
Исходники ucode, dnsmasq, upstream CSQTT и SDK закреплены версией или хешем.
Собранные ARM64-бинарники дополнительно запускаются через QEMU Cortex-A53:
проверяются отказ от некорректного конфигурационного файла и команда брокера.
Извлечённый клиент дополнительно создаёт настоящий Linux TUN в namespace
без внешней сети: проверяются private control/status, stop, SIGTERM, удаление
TUN после SIGKILL и запуск после оставшегося socket. Подключение к серверу/VK
и работу прошивки подтверждают отдельно на роутере. SDK кеширует зависимости,
но три пакета проекта каждый
раз очищаются и собираются из текущих исходников. Полные журналы SDK сжимаются
и сохраняются как диагностика при ошибке.

Артефакты CI без подписи подходят для проверки сборки. Установщик принимает
только пакеты и manifest, подписанные ключом проекта.

## Ключ выпуска

Публичный ключ хранится в `release/csqtt-public.pem` и встроен в `install.sh`.
Локальный приватный ключ создан в `.work/signing/release.pem`; файл исключён
из Git. Его нужно хранить отдельно и не отправлять в сообщения или логи.
Владелец репозитория может сохранить содержимое файла в Actions secret
`CSQTT_SIGNING_KEY`. Ключ передаётся только шагу подписи, временный файл удаляется.
Также поддерживается имя `secret1`, выбранное владельцем репозитория;
`CSQTT_SIGNING_KEY` имеет приоритет, если настроены оба секрета.
До установки зависимостей и сборки SDK CI проверяет, что значение является
полным PEM приватного ключа, соответствует публичному ключу проекта и может
создать проверяемую подпись. Ошибка выводится без значения секрета и деталей
криптографического парсера. Кавычки, путь к файлу или текст с буквальными `\n`
вместо переносов строк не являются содержимым PEM-файла.
Скрипт сборки проверяет соответствие публичному ключу проекта и подписи всех
трёх пакетов. Перед сборкой зависимостей ключ удаляется из их окружения.

`Build signed draft release` запускается вручную с уже существующим тегом вида
`v0.1.0-preview.N`. Владелец создаёт тег на commit, прошедшем проверки, и
отправляет его в репозиторий. В следующей схеме замените `N` номером preview,
а `VERIFIED_COMMIT_SHA` полным хешем проверенного commit:

```sh
git tag v0.1.0-preview.N VERIFIED_COMMIT_SHA
git push origin refs/tags/v0.1.0-preview.N
gh workflow run draft-release.yml --ref v0.1.0-preview.N -f tag=v0.1.0-preview.N
```

Для первого ручного запуска файл workflow должен быть в default branch
`main`; там же он должен находиться для появления кнопки **Run workflow**.
При запуске через интерфейс выберите ref с тем же commit, на который указывает
тег. [Условия workflow_dispatch](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_dispatch).

Preflight проверяет наличие ключа, формат тега и точное совпадение commit тега
с `GITHUB_SHA` до долгой сборки. Затем workflow выполняет весь CI, проверяет
подпись manifest и хеши пакетов и создаёт черновик предварительного выпуска
с `--verify-tag`. Существующий тег позволяет использовать штатный
`GITHUB_TOKEN`, не создавая им тег на commit с изменёнными workflow.
[Условия создания release](https://docs.github.com/en/rest/releases/releases#create-a-release).

Номер `N` в `v0.1.0-preview.N` задаёт ревизию всех трёх пакетов `0.1.0-rN`.
Для следующей сборки увеличивайте его: APK должен видеть более новую версию,
чтобы обновление действительно заменило установленные файлы.

## Подписанный preview.6: запуск CAPTCHA Helper

Собран подписанный **v0.1.0-preview.6** с ревизией трёх пакетов `0.1.0-r6`.
Исходный commit `1d9c470dd89e7b820ff13c91fd3d7531181bfb9e` и commit сборки
`e274bedca1a72d0d8e03073abf1838f4a809fe8d` имеют дерево
`5f1455bebd8fc49828e64e89354c3d7a816661f9`. В единственном запуске
[CI37752081113](https://github.com/RATOR2000/csqtt-openwrt/actions/runs/37752081113)
ветки `codex/preview.6-build` прошли checks, core, native-policy и openwrt.

В свежем CI прошли 73 теста политик/LuCI/перезагрузки службы и 2 теста выпуска
на Node, 4 теста выпуска на Python, 353 Rust-теста и отдельный тест TURN;
7 прежних Rust-тестов сохраняют статус ignored. После сборки прошли 22 теста
на упакованном LuCI и 6 тестов перезагрузки на упакованном init. Подтверждены
подписи трёх APK и manifest, соответствие пакетов замороженным исходникам,
нативные ucode/DNS/nftables, ARM64 запуск и настоящий Linux TUN. При сверке
overview.js учтено точное удаление одного переноса строки minifier SDK после
оператора `+`; остальные байты совпадают. Android APK повторно использует
проверенные исходные байты, Android, брокер, установщик и транспорт не менялись.

Изменение LuCI открывает CSQTT Helper отдельным нажатием на Android intent.
Ссылка возврата ведёт на обзор того же роутера и не содержит одноразового
разрешения; на компьютере используется ручное копирование ссылки. Автоматические
тесты не подтверждают запуск установленного Android-приложения или решение
настоящей CAPTCHA. Эти проверки остаются в ACCEPTANCE.

Публичный preview.6 проверен: тег указывает на точный commit сборки, размеры,
SHA256 и скачанные копии всех восьми файлов совпадают. Подписанное обновление
до r6 завершилось с кодом 0: четыре файла настроек сохранены, все 11 установленных
файлов совпадают с подписанными APK. Проверены 72 канала, DNS и разные выходы
WAN/VPN. Результаты аварийных испытаний r5 ниже относятся к r5.
Команда preview.6 для GL-MT6000 / OpenWrt 25.12.5 от root:

```sh
uclient-fetch -O /tmp/csqtt-install.sh https://github.com/RATOR2000/csqtt-openwrt/releases/download/v0.1.0-preview.6/install.sh && sh /tmp/csqtt-install.sh v0.1.0-preview.6
```

## Предыдущий подписанный preview.5

Опубликован [v0.1.0-preview.5](https://github.com/RATOR2000/csqtt-openwrt/releases/tag/v0.1.0-preview.5)
для испытаний на GL-MT6000 / OpenWrt 25.12.5 из проверенного commit
`38e0283f724aa3110cfc75ad22f9bf57801e4b80`. В запуске
[CI37464598550](https://github.com/RATOR2000/csqtt-openwrt/actions/runs/37464598550)
workflow `Preview 5 build` успешно завершились все четыре задачи: checks,
core, native-policy и openwrt. Свежий запуск Rust дал 353 успешных теста,
0 ошибок и 7 тестов с прежним статусом ignored. Все 11 проверок liveness прошли.
Нативные проверки ucode/DNS/nftables и сборка SDK прошли; проверены запуск
ARM64-клиента, настоящий Linux TUN, подписи трёх APK и manifest, точная ревизия
`0.1.0-r5` и восстановление DNS без сети. Прошли все 71 тест политик/LuCI и
перезагрузки службы на исходниках, 20 тестов на упакованном LuCI и 6 проверок
перезагрузки службы на упакованном init. Проверки настоящим ucode подтверждают
флаги устройства, исключение выключенных устройств из политик/DNS/IPv6,
сохранение записи и обратное включение. Упакованные init, runtime, manage,
policy и пять ресурсов JavaScript сверены с замороженными исходниками;
для init также проверены права 0755.

Android APK совпадает байт в байт с проверенным артефактом
[CI36757684228](https://github.com/RATOR2000/csqtt-openwrt/actions/runs/36757684228).
Workflow подтверждает успешные прежние проверки и происхождение артефакта,
а также неизменность исходников Android, брокера и установщика. Транспорт на Rust
и нативные политики проверены заново до сборки SDK. Подписи пакетов и manifest
подтверждены ключом проекта. После публикации проверены размеры, SHA256 и
содержимое всех восьми файлов через API GitHub и скачивание публичных assets.
Тег указывает на точный commit сборки; выпуск отмечен как предварительный.

Preview.5 содержит галочку активности каждого назначенного устройства и
сохранение работающего процесса VPN при применении политик с неизменными
настройками подключения. На реальном роутере исправленные исходники поверх r4
прошли переключение отдельного тестового устройства через LuCI VPN → WAN → VPN:
HTTPS использовал нужный выход, DNS и локальная панель работали, выключенная
запись сохранялась, прежние conntrack-записи удалялись, PID клиента сохранялся.
Настройки владельца сохранены. После этого подписанное обновление до r5
завершилось с кодом 0: все три пакета имеют ревизию r5, четыре файла
конфигурации сохранены без изменений, 11 установленных файлов совпадают с
подписанными пакетами. VPN подключён, работают 72 канала; DNS роутера и группы,
HTTPS через WAN и VPN с разными внешними адресами проверены.

В preview.4 каждое TURN-соединение использует существующие аутентифицированные
сообщения READY/READY_OK оригинального протокола v2.1.9: проверка каждые 60 секунд,
пять секунд на отправку и ответ, три последовательных пропуска вызывают
штатное завершение соединения и переподключение. Сервер менять не требуется.
Также включены исправления готовности DNS и сохранения канонического TCP в LuCI.
На подписанной r4 прошла проверка потери входящих ChannelData одного соединения:
через 133 секунды появился ровно один тайм-аут READY и клиент пересоздал канал.
Остальные 71 исходный сокет сохранились, восстановлены все 72 потока.
Пакеты STUN продолжали проходить, ошибок локальной отправки и тайм-аутов TURN
не добавилось. Процесс клиента и четыре файла настроек не изменились;
временное правило удалено. После восстановления DNS и HTTPS через VPN работают,
а десять установленных файлов совпали с подписанным пакетом. Это проверяет
механизм восстановления; устранение ежедневных потерь требует наблюдения.

Установщик `install.sh` не менялся с проверенного выпуска и сохраняет
исправления preview.1: проверяет
архитектуру прошивки и базы APK, сохраняет подписанные индексы OpenWrt и точную
исходную версию DNS в отдельном кеше. OpenWrt подписывает индекс репозитория;
индивидуальный `dnsmasq.apk` не подписан. Перед изменением DNS установщик
действительно восстанавливает исходный пакет в изолированной копии без сети
и скриптов пакетов, затем сравнивает версии всех установленных пакетов.
Проверка доверия включена на всех этапах; откат использует точную версию
и сохранённый индекс. 36 локальных сценариев прошли; [проверка на настоящем
APK3.0.5](https://github.com/RATOR2000/csqtt-openwrt/actions/runs/36739033136)
подтвердила подписи, отказы для повреждённого DNS/неверного ключа, кеш и
восстановление без сети. Подписанные пакеты и тег preview.1 сохранены.
Реальное подписанное обновление до r4 завершилось с кодом 0: все три пакета
имеют версию `0.1.0-r4`, конфигурации csqtt, dhcp, firewall и network сохранены.
Закрытая резервная копия осталась на роутере; после обновления подтверждены
подключение и 72 потока. DNS, IPv4 VPN, WAN-исключение, остановка/восстановление
туннеля и `fw4 reload` проверены на preview.2; исправление готовности DNS затем
прошло реальное повторное испытание. На r5 дополнительно проверены аварийное
завершение клиента, защита при обычной загрузке и маршрутизируемые TCP/UDP IPv6
через изолированный узел до/после `fw4 reload`. Ручная Android CAPTCHA и
остальные незакрытые пункты ACCEPTANCE остаются условиями стабильного выпуска.
Assets содержат установщик, три APK,
подписанный manifest, контрольные суммы и отладочный APK помощника.
Для GL-MT6000 с OpenWrt 25.12.5 команда preview.5 от root:

```sh
uclient-fetch -O /tmp/csqtt-install.sh https://github.com/RATOR2000/csqtt-openwrt/releases/download/v0.1.0-preview.5/install.sh && sh /tmp/csqtt-install.sh v0.1.0-preview.5
```

Аргумент тега выбирает assets этого preview. `latest` предназначен для
полного опубликованного release: GitHub не назначает prerelease или draft
последним release. [Правила latest](https://docs.github.com/en/rest/releases/releases#create-a-release).

## Локальная Linux-сборка

Нужны Rust 1.97.1, Go 1.26.8, Python 3, инструменты сборки SDK и пакеты из
шага `Build dependencies` workflow. Команда: `bash scripts/build-sdk.sh`.
При наличии приватного ключа в `CSQTT_SIGNING_KEY` также создаётся подпись.
SDK загружается в `.work/sdk`, результат — в `dist`; оба каталога исключены из Git.

## Условия стабильного выпуска

Нужны успешные сборки трёх пакетов и Android-помощника, проверка установщика
на целевой версии APK/OpenWrt, а затем реальные проверки на GL-MT6000:
подключение к серверу, смешанные WAN/VPN группы, DNS/IPv6, остановка и сбой
клиента, перезагрузка firewall/роутера и ручная CAPTCHA с телефона в VPN-группе.
Секреты и VK-ссылки остаются на устройствах. Результаты фиксируются в STATUS.
Порядок реальных испытаний: [ACCEPTANCE.md](ACCEPTANCE.md).

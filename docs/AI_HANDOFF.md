## Что это за проект

Пакеты `csqtt`, `csqtt-captcha`, `luci-app-csqtt` добавляют оригинальный CSQTT на OpenWrt: один VPN-туннель, группы устройств, правила по доменам/IP и управление через LuCI. Отдельное Android-приложение помогает пройти настоящую CAPTCHA VK. Серверный протокол не заменялся.

Версия **2.1.9 выбрана намеренно** ради совместимости с существующими клиентами, включая Windows. Обновление номера upstream само по себе не повод менять протокол. Сохраняются лицензия PolyForm Noncommercial и авторство upstream.

Целевой сценарий: **одна команда из README → автоматическая установка зависимостей → мастер в браузере**. До завершения мастера VPN выключен. Новая установка использует консервативный профиль из девяти соединений; существующие ручные настройки сохраняются.

## Что уже сделано и подтверждено

- [Preview.10 опубликован](https://github.com/RATOR2000/csqtt-openwrt/releases/tag/v0.1.0-preview.10), инструкция находится в `main`. Все 418 опубликованных файлов независимо сверены; установщик привязан к точному preview-тегу, без зависимости от GitHub `latest`.
- Завершены установочные backend `opkg/ipk` и `apk`: проверка платформы/ABI/ресурсов, подписей и официальных зависимостей, точного ядра для TUN, изолированная проверка установки и отката, постоянный журнал, резервная копия и восстановление после прерывания.
- Шесть SDK-профилей: **24.10.8, 25.12.5, 25.12.6** × **`mediatek/filogic` / `aarch64_cortex-a53`** и **`x86/64` / `x86_64`**. Сборка, проверка ABI и эмуляция не означают поддержку всех ARM64-роутеров.
- Пройдены пять общих CI jobs, шесть SDK-сборок и три чистых OpenWrt VM. Отдельно проверена подписанная ARM-миграция r9 → r10 → r9 в изолированной базе APK; её пакетные скрипты не запускались.
- Буквальная публичная команда README прошла на чистых **24.10.8 и 25.12.6**: установка недостающих LuCI/OpenSSL tool/TUN, работа runtime/DNS/firewall/LuCI, повторная установка с сохранением настроек, удаление с сохранением управления и штатного DNS.
- На реальном **GL-MT6000 с официальной 25.12.6** подтверждены установка, целостность установленных файлов, завершённая транзакция, LuCI, WAN/VPN/DNS и подключение девяти потоков. Это первоначальная проверка работоспособности, без нагрузочного испытания или имитации отказов.
- Реализованы авторизация без блокировки остальных групп ожиданием CAPTCHA, защита активного Helper-сеанса, отклонение отменённых ответов, проверки свежести статуса и готовности каналов.
- Реализованы раздельные WAN/VPN/DNS-пробы и ограниченное восстановление с сериализацией Stop/Reload/Helper/установки. **Автоматический перезапуск по отказу VPN пока выключен по умолчанию** (`auto_recover=0`); наблюдатель procd работает отдельно, обычные переподключения отдельных каналов сохраняются.
- Используется отдельный DNS-процесс CSQTT. Штатные DHCP/DNS сохраняются. VPN-DNS не имеет прямого WAN-fallback; IPv6-интернет для защищаемых групп блокируется, локальное управление сохраняется.

## Что ещё не завершено

1. Полная приёмка стабильности preview.10 на устройстве: контролируемые отказы, сохранение guards/LAN, отсутствие выхода защищённого трафика в WAN, конкуренция Stop/Reload/Helper/recovery и лимиты восстановления.
2. Новые подтверждённые **72 часа** обычной эксплуатации. Старое наблюдение preview.9 прервано перепрошивкой и **не завершено**. Календарное время не является доказательством. Только после оговорённой приёмки рассматривается включение автоматического восстановления по умолчанию.
3. Полная проверка реального Android Helper и CAPTCHA VK: начало, завершение, отмена, истечение, отклонение поздних ответов. APK в релизе — debug-сборка.
4. Загрузка после неудачной первой активации — отложенный boot7-gate. Материалы есть в `tests/router/boot7/`; **это вмешивающиеся тесты, не запускать на основном роутере автоматически**.
5. Измерения CPU/памяти/пропускной способности, более высокие автоматические профили, расширение проверенных ABI: ARMv7, затем отдельная адаптация атомарных операций/сборки для MIPS. Штатная прошивка GL.iNet исключена из текущего этапа.
6. Небольшая известная проблема журнала: ранний package post-install может написать `Platform is not qualified` до записи подписанного допуска установщиком. Транзакция затем завершается и работает. Устранять преждевременный вызов, сохраняя проверку допуска; обходить защиту платформы нельзя.

Если новой задачи нет, безопасный следующий шаг — последний пункт: исследование порядка post-install и узкий regression-тест в изолированной среде. Работоспособный роутер для этого менять не требуется. Публикация следующего релиза — отдельный этап после проверок.

## Как продолжать безопасно

- Начни с `git status --short`, `git log -5 --oneline` и просмотра нужных исходников. Не повторяй уже завершённый выпуск. Выбирай проверки по изменению; документация не требует повторной сборки всей SDK-матрицы. Для установщика проверяй `python scripts/assemble-installer.py --check`: `install.sh` генерируется из исходных частей.
- Команды остальных тестов бери из актуального CI и `docs/BUILD.md`. Скрипты `test-openwrt-guest.sh`, VM/boot/fault-сценарии предназначены для указанного в них стенда; не запускай их на основном роутере.
- Сохраняй один туннель, настройки, идентичность, recovery budget, LAN и явные WAN-исключения. Не заменяй системный firewall/DNS. Ограничения классификации доменов через кеши, общие IP и независимый DoH описаны в контракте.
- Штатная LuCI может вернуть **403 с заголовком авторизации и полной формой входа**. Проверяющий стенд уже учитывает этот контракт; любая произвольная 403 не означает исправную панель.
- GitHub меняет `~` в именах assets. Используй предусмотренную нормализацию имён и подписанный provenance. Байты пакетов и источник квалификации сохраняются; после изменения метаданных проверяются все связанные подписи/хеши.
- Не отключай TLS, подписи или контроль зависимостей. Не подменяй `GITHUB_SHA` ради чужих доказательств, не генерируй новый ключ доверия при отсутствии старого. Публичный ключ проверки — `release/csqtt-public.pem`; приватный ключ не хранится в Git и не передаётся через чат.
- Теги и файлы опубликованных релизов сохраняй неизменными. Preview.8 отозван; не устанавливай его. Новые изменения получают новый номер после проверки актуальных релизов.
- В новом аккаунте доступ к GitHub на запись, CI secrets, SSH, браузерная авторизация и прежние агенты **не появляются автоматически**. Проверь реальные возможности. `.work/` и `dist/` игнорируются и не входят в этот чекпоинт; их отсутствие не повод выдумывать результаты или запрашивать публикацию секретов.
- Рабочую среду определяй заново. На исходной станции использовались Windows/PowerShell и CI для Linux/Rust/Android/SDK; личные пути не нужны. Инструменты могут уже быть доступны. SSH-цель и разрешённый объём действий согласуются отдельно и не записываются в публичные документы.
- Обновляй STATUS после значимого результата: что изменено, чем проверено, что осталось и следующий шаг. Делай небольшие checkpoint-коммиты; не называй непроверенный checkpoint релизом. Не создавай запланированные задачи Codex; штатный procd-наблюдатель программы сохраняется.

# Испытания на GL-MT6000: preview.7

Подписанная установка/обновление r7 и подключение к реальному серверу проверены
на роутере. На r5 проверены смешанные политики IPv4, аварийное восстановление,
защита при загрузке и маршрутизируемые TCP/UDP IPv6 до/после перезагрузки firewall;
подробности и границы доказательств — в STATUS.md.
IPv6 проверялся через изолированный тестовый узел; IPv6 провайдера не проверен.
Исправление DNS при неудачном первом применении проверено отдельно на нативных
процессах роутера в изолированной сети: UDP/TCP к портам 53 и 5400 не достигают
внешнего тестового DNS. Восстановление сохранённой защиты через firewall и снятие
защиты после успешного применения проверены; реальная загрузка роутера именно
с неудачным первым применением пока не проверена. Подробности — в STATUS.md.
Исправление входит в подписанный r7, установленный на роутере. Четыре файла
настроек сохранены, 11 установленных файлов совпадают с подписанными пакетами,
работают 72 канала, DNS и разные выходы WAN/VPN. Обе временные цепочки защиты
пусты, сохранённый файл содержит снятие обеих блокировок.
Ручная CAPTCHA и остальные незакрытые пункты ниже проверяются
отдельно. Сборка SDK, QEMU и Linux namespaces в CI их не подтверждают.
Подготовьте резервную копию настроек и проводное устройство для доступа к LuCI.
Подключение агента к роутеру требует его адреса и согласованного объёма работ.

## Подготовка

- Официальная OpenWrt 25.12.5 на GL-MT6000; установочные пакеты проверены
  ключом проекта. Зафиксируйте тег/commit и результат установки.
- Сервер из оригинального CSQTT v2.1.9 работает, создан клиент, известны
  параметры подключения и действующие звонки VK. Значения вводятся в LuCI.
- Три локальных устройства: A — VPN-группа, B — WAN-группа с VPN-правилом,
  C — вне групп. Android-телефон с Helper может быть устройством A.
- Доступен собственный внешний HTTP/UDP endpoint, где можно проверить
  исходящий IP. Разные WAN/VPN-адреса позволяют увидеть маршрут.

## Что подтвердить

| Проверка | Ожидаемый результат |
|---|---|
| Подключить клиент | В LuCI появляется туннельный IPv4, соединение с сервером проходит |
| A: обычный ресурс и WAN-исключение | Обычный ресурс идёт через VPN, исключение через WAN |
| B: обычный ресурс и VPN-правило | Обычный ресурс идёт через WAN, правило через VPN |
| C: обычный ресурс | Использует WAN при любом состоянии CSQTT |
| Пересекающиеся домены/IP/подсети | Более раннее подходящее правило имеет приоритет |
| Остановить клиент; затем завершить процесс аварийно | VPN-ресурсы A/B недоступны; WAN-исключения, C и LuCI доступны |
| Восстановить клиент | VPN-ресурсы снова доступны без снятия защиты |
| DNS при работающем и остановленном туннеле | VPN-запросы не уходят к WAN-резолверу; WAN-исключения и локальные имена работают |
| DNS клиента настроен на внешний IPv4 | Запрос на порту 53 обслуживается контекстом группы |
| Первое применение политики завершилось ошибкой до настройки DNS | DNS защищённых устройств закрыт; незакреплённые устройства и доступ к LuCI по IP работают. Защита сохраняется после восстановления firewall и загрузки роутера |
| Интернет и локальная сеть по IPv6 | Интернет защищённых групп заблокирован; локальный IPv6 доступен |
| Перезагрузить firewall, затем роутер | Защита сохраняется; прямые исключения и локальное управление доступны |
| Изменить политику во время активного соединения | Старое соединение не продолжает обходить новую политику; после переподключения действует новое правило |
| Первая активация завершилась ошибкой | После reboot сохраняется защитная блокировка предложенных VPN-устройств |
| Ручная CAPTCHA на телефоне из VPN-группы | VK открывается через мост, решение восстанавливает подключение |
| CAPTCHA отменена/истекла/заменена | Старый Helper-сеанс и ответ не влияют на новый запрос |
| Повторная установка/обновление | Настройки и клиентская идентичность сохраняются, работают новые службы |
| Ошибка/прерывание первой замены dnsmasq | Восстановлены исходный DNS-пакет, DHCP-настройки и APK world |

Заранее не называйте неуспешный HTTP-запрос доказательством блокировки: также
проверьте журнал своего endpoint или захват исходящего трафика на WAN. Для DNS
используйте новые имена/очищенный кеш. Отдельно проверьте UDP и TCP, а для
firewall/boot — уже открытые соединения.

## Сохранить результат

В STATUS запишите версию пакетов, прошивку, сценарий и результат каждого
пункта. Диагностику экспортируйте через LuCI. Не добавляйте в Git конфигурацию
с паролем, ссылками VK, grant или внутренней идентичностью клиента.
Стабильный выпуск возможен после подтверждения этих сценариев.
